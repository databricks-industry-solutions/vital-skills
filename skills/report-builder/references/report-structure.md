# Report Structure and LaTeX Templates

This document provides two LaTeX templates and section-by-section guidance for generating scientific reports from notebook work.

## Template choice

Ask the user which template they want (or infer from context):

| Template | When to use | Style |
|---|---|---|
| **REVTeX PRL preprint** (default) | Publication-quality report, compact layout | Computer Modern serif, APS-style sections, `ruledtabular`, abstract block, no line numbers |
| **REVTeX PRA preprint** | Longer reports needing more spacious layout | Same as PRL but wider spacing |
| **Internal report** | Quick internal summary, lab notes, team reports | Serif, fancyhdr, lightweight, no journal boilerplate |

If in doubt, use **REVTeX PRL preprint** — it looks professional, compact, and the user can always switch to PRA for more space.

---

## Template 1: REVTeX PRL preprint (default)

REVTeX 4.2 is the standard LaTeX class for APS journals (Physical Review A/B/C/D/E/Letters). The `preprint` option produces a wide single-column layout ideal for reports and pre-prints. PRL gives a more compact feel than PRA. No supporting files needed — Tectonic auto-downloads the `revtex4-2` package. For PRA, change `prl` to `pra` in the `\documentclass` line.

### CRITICAL: REVTeX package conflicts

- **Do NOT load `hyperref`** — REVTeX loads it internally. Duplicate loading causes `TeX capacity exceeded [parameter stack size]` and compilation fails.
- **Do NOT load `float`** — use `[htbp]` instead of `[H]` for figure placement.
- **Do NOT load `natbib` explicitly** — REVTeX handles citations internally.
- Use `\begin{ruledtabular}` for tables (APS house style).
- For inline references without a `.bib` file, use `\begin{thebibliography}{N}...\end{thebibliography}`.

### REVTeX PRL preprint template structure

**Section order**: Abstract → Introduction → Results (scientific highlights only) → Discussion → References → Methods (`\small` font) → Code availability → Data availability.

Methods lives **after** the bibliography, matching Nature/Cell/Science convention. It is wrapped in `\begingroup\small ... \endgroup` to visually signal supplementary detail.

### REVTeX section-by-section guidance

- **Abstract**: Single paragraph in `\begin{abstract}`, 150 words max. State what was done, how, and the main finding. This is a rough draft the user will rewrite.
- **Keywords**: 3-10 terms via `\keywords{}`.
- **Introduction**: Brief context in 2-3 flowing paragraphs (not bullets). What question, why it matters, what approach.
- **Results**: **Scientific highlights only.** Subsection titles must be scientific findings ("CUX2-LAMP5 neurons are enriched in AD"), not pipeline checkpoints ("Quality control retained 84.5% of cells"). Rule of thumb: if a subsection title could appear in the Methods of a published paper, it belongs in Methods, not Results. If no notable scientific findings emerged, use a brief paragraph referencing the figures without subsections. QC/diagnostic figures go in Methods, not here.
- **Discussion**: Bullet-form interpretation and limitations. The agent flags patterns; the user expands.
- **References**: Placed before Methods. Use `\begin{thebibliography}` for inline refs or `\bibliography{}` with a `.bib` file.
- **Methods** (after references, `\small` font): The agent's primary deliverable. Full journal-quality prose — see the detailed Methods guidance below. Wrapped in `\begingroup\small ... \endgroup`. QC/diagnostic figures go here.
- **Code availability**: Separate top-level section at normal font (outside `\endgroup`). Notebook path, MLflow experiment, run ID.
- **Data availability**: Separate top-level section. Source paths, dimensions, accession numbers.
- **Tables**: Use `\begin{ruledtabular}` inside `\begin{table}` for APS house style. Software table uses multi-column layout.
- **Figures**: Place with `[htbp]` (NOT `[H]`). Use `width=0.95\columnwidth`. Caption must be a full sentence.
- **Paths**: Use `\fpath{}` with `\allowbreak` after `/`, `-`, `_`, `@` for paths longer than ~40 characters. Do NOT use `\nolinkurl` (unavailable in REVTeX). Short identifiers (`\texttt{.raw}`, `\texttt{donor\_id}`) stay as `\texttt{}`.

### Content balance: Methods-heavy, Results-light

**The report is Methods-centred.** The agent writes a thorough, journal-quality Methods section (its primary deliverable, the one section where it has authoritative knowledge). The Results section is kept light — only scientific highlights with brief descriptions and figure captions that the researcher will expand.

This reflects how the tool is used: the agent knows the computational steps in detail (it wrote them), but the researcher owns the scientific narrative.

### Front-page disclaimer (REQUIRED)

The first page of every report must include this notice, placed between the abstract and the introduction:

```latex
\begin{center}
\fbox{\parbox{0.9\columnwidth}{\small
\textbf{Note:} This report was generated by Genie in collaboration with a researcher,
but requires careful review and editing prior to sharing with others.}}
\end{center}
```

Do NOT omit this. It must appear in every generated report.

### Methods: depth and reproducibility (applies to ALL templates)

**The Methods section must be detailed enough for another researcher to reproduce the analysis from scratch.** This is the primary content deliverable of the report. Write it as journal-quality prose — not code snippets, not bullet lists of function calls. Every parameter and threshold should be woven into descriptive sentences, as in a published paper.

#### Writing style for Methods

- **Prose, not code.** Write "Counts were normalized to 10,000 per cell and log-transformed" — not "`normalize_total(target_sum=10000)` followed by `log1p()`". Use `\texttt{}` sparingly for package names or file paths, never for inline code.
- **Passive voice is fine** for methods (standard in journals): "Cells were filtered", "Clustering was performed".
- **Organize by workflow stage**, not by notebook cell order: Data Sources → Preprocessing → Analysis → Statistical Testing.
- **State decisions and rationale**: if a step was considered but rejected, say so and why.

#### Data Sources
Write as flowing prose. Cover:
- Full path (use `\fpath{}` with `\allowbreak`) or fully qualified table name
- Dimensions: row count, column count, date range
- Key columns or features used in the analysis
- Any filters applied and the rationale
- File format and any format-specific loading details (e.g., "raw counts were extracted from the `.raw` slot; Ensembl gene identifiers were mapped to gene symbols using the `feature_name` annotation column")
- Gene/feature mapping success rate when applicable (e.g., "24,902 of 33,091 genes (75.3%) mapped")

#### Preprocessing
For EACH transformation step, describe in **flowing prose** (no bullet lists):
- **What** was done (filtering, QC, normalization, imputation, feature selection)
- **Why** (e.g., "to exclude empty droplets and doublets")
- **Every parameter** with its value, woven into the sentence (e.g., "Cells expressing fewer than 450 or more than 2,300 genes were excluded")
- **How thresholds were derived** (e.g., "Thresholds were set at the median plus three times the median absolute deviation of each metric's distribution, selecting the tighter of the MAD bound and the 95th percentile")
- **Counts before and after** each major filtering step (e.g., "retaining 47,679 of 51,876 cells (91.9%)")
- **Steps considered but rejected** and why (e.g., "Doublet detection via scrublet was considered but not performed: the dataset consists of FACS-sorted nuclei with well-characterised subtypes and exhibited no strong doublet signature")
- **Why uniform vs. per-sample thresholds** when applicable

#### Analysis / Modeling
- **Algorithm**: exact name and variant in prose (e.g., "Community detection was performed using the Leiden algorithm (igraph implementation)" — not "Leiden clustering")
- **Every hyperparameter**: resolution, n_neighbors ($k$), n_components, n_top_genes, etc., stated in the sentence (e.g., "$k=15$ nearest neighbours")
- **Statistical tests**: name the test and correction method; note pseudobulk caveats if single-cell-level testing was used
- **Compute environment**: e.g., "All analyses were performed on Databricks Serverless Compute (CPU)"

#### Software versions table (REQUIRED)

At the end of the Methods section, include a table listing every key package and its exact version.

**Resolve versions programmatically (REQUIRED).** Before writing the `.tex`, run this on the notebook compute to get exact versions:

```python
import importlib.metadata, sys
for pkg in ['scanpy','anndata','harmonypy','numpy','pandas','matplotlib',
            'seaborn','mlflow','scipy','igraph','leidenalg','scikit-learn','zarr']:
    try: v = importlib.metadata.version(pkg)
    except: v = '?'
    print(f'{pkg}: {v}')
print(f'Python: {sys.version_info.major}.{sys.version_info.minor}.{sys.version_info.micro}')
```

Embed the exact versions in a **multi-column table** (Package/Version/Package/Version) to save vertical space:

```latex
\begin{table}[htbp]

\begin{ruledtabular}
\begin{tabular}{llll}
Package & Version & Package & Version \\
\hline
Python & 3.12.3 & numpy & 2.3.4 \\
scanpy & 1.10.4 & pandas & 2.3.3 \\
anndata & 0.10.9 & scipy & 1.16.3 \\
\end{tabular}
\end{ruledtabular}
\end{table}
```

Use `\todo{verify}` only as a last resort when the notebook compute is unreachable.

#### Example of insufficient vs. sufficient Methods

**Insufficient** (too vague to reproduce):
> Data was filtered for quality, normalized, and clustered. Marker genes were identified using differential expression.

**Sufficient** (reproducible prose):
> Cells expressing fewer than 450 genes, more than 2,300 genes, or more than 6\% mitochondrial reads were removed. Thresholds were derived from the median plus three times the median absolute deviation of each QC metric's distribution, retaining 47,679 of 51,876 cells (91.9\%). Counts were normalized to a target sum of 10,000 per cell and log-transformed. The 2,000 most highly variable genes were selected using the Seurat v3 method. Principal component analysis was computed on 50 components, of which the top 30 were used to construct a nearest-neighbor graph ($k$=15). Two-dimensional embeddings were generated with UMAP using default parameters. Community detection was performed with the Leiden algorithm at resolution 1.0, yielding 17 clusters. Differentially expressed marker genes were identified per cluster using the Wilcoxon rank-sum test.

#### Code and Data Availability (REQUIRED — separate sections)

Code availability and Data availability are **separate top-level `\section{}` entries**, placed after the `\endgroup` that closes the smaller Methods font, so they render at normal body size. Use `\fpath{}` with `\allowbreak` for long paths:

```latex
\section{Code availability}
The analysis notebook is available at
\fpath{/\allowbreak Users/\allowbreak user@\allowbreak example.com/\allowbreak project/\allowbreak Analysis Notebook}
in the Databricks workspace. Experiment tracking: MLflow experiment
\fpath{Analysis Notebook\_\allowbreak experiment}.
\todo{Add public repository or DOI if applicable.}

\section{Data availability}
Source data are stored in
\fpath{/\allowbreak Volumes/\allowbreak catalog/\allowbreak schema/\allowbreak volume/\allowbreak data/}.
\todo{Add accession number or data sharing agreement details.}
```

### Results: content depth and gating

**Results contain only scientific highlights.** The agent provides:
- Brief factual descriptions of scientific findings (compositional shifts, differential expression signatures, dose-response patterns) — not pipeline checkpoints
- Figure captions that describe what is shown (axes, panels, color encoding) and state the key observation
- An optional intro paragraph referencing overview/validation figures with "see Methods" for technical details
- QC/diagnostic figures and tables belong in Methods, not Results
- Flagged discrepancies or unexpected findings (e.g., "cluster 16 markers suggest mast cells despite T cell annotation")

**The agent does NOT write extended scientific interpretation.** That is the researcher's job. The Results section is a scaffold the researcher will expand.

#### Gating question for deeper Results

If the conversation history shows the researcher has been discussing scientific interpretation with the agent (e.g., debating cell type annotations, interpreting batch effects, discussing biological mechanisms), the agent should ask:

> "I noticed we discussed [specific scientific topic] during the analysis. Would you like me to include that interpretation in the Results/Discussion sections, or do you prefer to write that yourself?"

Only include extended scientific narrative if the researcher explicitly says yes. Default is light.

## Shared guidance (applies to both templates)

### Title and author

- **Title:** Derive from the notebook name or the first markdown heading. Make it descriptive: "Dose-Response Analysis of Compound X in Phase II Cohort" not "Analysis Results".
- **Author:** Use the notebook owner's display name if available from the workspace context. If unknown, use `\todo{Author name}`.
- **Short title** (for Internal Report header): Abbreviate to ~40 characters.

### Figures

#### Export format: always save both PDF and PNG

The notebook export cell must save **every figure in both PDF and PNG**:
- **PDF** for LaTeX `\includegraphics` — vector text/axes stay crisp at any zoom
- **PNG** at 300 DPI for previews, slides, and web

The `\includegraphics` references in the `.tex` file should use `.pdf`
extensions (not `.png`). LaTeX handles PDF figures natively and the result is
sharper than raster at every display size.

For scatter plots with >5,000 points (UMAP, QC scatter, embeddings), the
notebook code should use `rasterized=True` on the scatter artist so the PDF
has hybrid vector+raster: crisp vector text/axes/legends with rasterized data
points, keeping file size manageable. See the scientific-figures skill Export
section for details.

#### Placement and sizing

For each figure the notebook produces:

1. **Copy both files** (`.pdf` and `.png`) to the build directory.
2. Use `[width=0.85\textwidth]` as the default. Reference the `.pdf` file.
   For side-by-side figures, use `minipage`:

```latex
\begin{figure}[htbp]
  \centering
  \begin{minipage}{0.48\textwidth}
    \centering
    \includegraphics[width=\textwidth]{figures/fig_left.pdf}
    \caption{Left panel description.}
  \end{minipage}\hfill
  \begin{minipage}{0.48\textwidth}
    \centering
    \includegraphics[width=\textwidth]{figures/fig_right.pdf}
    \caption{Right panel description.}
  \end{minipage}
\end{figure}
```

3. **Caption is critical.** Write a full sentence: what the figure shows, what the axes are, and what the key takeaway is. The user will refine later, but a good starting caption saves time.
4. For REVTeX: use `[htbp]` placement (do NOT use `[H]` — the `float` package conflicts with REVTeX). For Internal Report: `[H]` with `float` package is fine.

### Finding figures in the notebook

Scan the notebook cells for figure output patterns:

| Pattern | Where the figure likely is |
|---|---|
| `plt.savefig("path")` | The path specified (workspace or volume) |
| `fig.write_image("path")` | Plotly export to the path specified |
| `fig.savefig("path")` | Same as matplotlib |
| `display(fig)` / `plt.show()` | Only in notebook output — not a file; ask user to re-save or re-run with `savefig` |
| `dbutils.fs.put(...)` | Written to DBFS/Volume path |

If figures exist only as notebook cell outputs (not saved to files), tell the user: "I found N figures displayed in the notebook but not saved to files. I'll add a cell to save them as both PDF and PNG so the report can include them. Where should I save them?"

### Discussion / Next Steps

- Interpretation of results (brief, bullet-form)
- Limitations or caveats the notebook reveals
- Planned follow-up analyses
- If the notebook has TODO comments or open questions, surface them here

### Bibliography

- If the user provides a `.bib` file: uncomment the `\bibliography` lines and use `\cite{key}` in the text.
- `unsrtnat` style works well for internal reports (numbered, in citation order).
- If no bib: leave the section commented out. The template compiles cleanly without it.
- If the user wants to write a full paper later, they can switch to a journal-specific `.bst` file.

## Tables in LaTeX

For notebook results that are tabular (e.g., model metrics, summary statistics), use `booktabs`:

```latex
\begin{table}[H]
  \centering
  \caption{<<TABLE_CAPTION>>}
  \begin{tabular}{lrrr}
    \toprule
    Model & Accuracy & AUC & F1 \\
    \midrule
    Logistic Regression & 0.82 & 0.87 & 0.79 \\
    XGBoost             & 0.91 & 0.94 & 0.89 \\
    \bottomrule
  \end{tabular}
  \label{tab:<<LABEL>>}
\end{table}
```

- Use `\toprule`, `\midrule`, `\bottomrule` (never `\hline`).
- Right-align numeric columns (`r`), left-align text (`l`).
- Keep tables narrow — if more than 5-6 columns, consider splitting or rotating.

## LaTeX special character escaping

When inserting content from notebook code or output into LaTeX body text, escape these:

| Character | Escape to | Notes |
|---|---|---|
| `_` | `\_` | Very common in Python identifiers and table names |
| `%` | `\%` | Common in formatted numbers |
| `&` | `\&` | Common in company names, table text |
| `#` | `\#` | Less common but breaks compilation |
| `$` | `\$` | Triggers math mode |
| `{` | `\{` | |
| `}` | `\}` | |
| `~` | `\textasciitilde{}` | |
| `^` | `\textasciicircum{}` | |
| `\` | `\textbackslash{}` | |

**Do NOT escape** inside:
- `\texttt{}` content (escape `_` only)
- `\verb|...|` content (no escaping needed)
- `verbatim` environments
- Math mode (`$...$` or `\[...\]`)

Helper approach for table/column names: wrap in `\texttt{table\_name}` — it looks appropriate for code identifiers and only requires `_` escaping.
