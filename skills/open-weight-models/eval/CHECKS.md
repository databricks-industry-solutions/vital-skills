# Checks the eval scores

Generated by `list_checks.py` from `expectations.json`, `corrected_checks.py` and
`practical_checks.py`; do not edit by hand. One section per model family, grouped by what the
check is about; a check lists the tasks it applies to. Severity: **critical** = the endpoint does not work or gives wrong results;
**major** = works but unsafe, ungoverned or not reproducible; **minor** = robustness or style.
The severity tables in the reports count failed *counted* checks only.

## teddy (teddy-001, teddy-002)

**Counted as:** *outcome* = measured on the live resources before teardown (`check_outcome.py`); *new* = read from the notebook code (`scorers.py`); *replicated* = a Sep–Oct 2026 sub-check, counted in its corrected form (`corrected_checks.py`) — *by intent* where the Sep–Oct logic matched literal text and now judges its goal, the original result kept as a ⚑ flag only; *convention* = reported, not counted.

## Practical checks — trial, not counted

Goal-based checks that accept any valid way of reaching each goal (`practical_checks.py`);
reported separately in each round, not used for the ship gate. `similarity_search_works`
applies to search tasks only.

| Check | Severity | Goal |
|---|---|---|
| `download_location_ok` | critical | Model files are downloaded and staged where serverless compute can write. |
| `xet_download_ok` | critical | The Hugging Face download of the TEDDY repository (Xet storage) completes. |
| `model_loads_with_pinned_deps` | critical | The served model loads: transformers 5.x is excluded (it breaks TeddyGModel) or not used, and the endpoint reached READY. |
| `fidelity_verified` | major | The wrapper's or endpoint's embeddings were compared against an upstream reference. |
| `signature_and_example` | critical | The logged model carries a signature and an input example (Unity Catalog needs the signature; the example grounds it in a real request). |
| `registered_in_uc` | major | The model is registered in Unity Catalog. |
