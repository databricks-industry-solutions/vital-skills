# Changelog

All notable changes to Vital Skills are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/).
Versioning follows [Semantic Versioning](https://semver.org/).

## 1.0.0 — Unreleased

First public release: Health & Life Sciences **Genie Code** skills, a generated
catalog, and a docs site. Clone the repo into Databricks, point Genie Code at
`skills/`, optionally sync to Unity Gateway.

### Added

**Skills** (Agent Skills `SKILL.md` bundles: references, scripts, tests, eval)

- Bioinformatics: `bulk-rnaseq`, `open-weight-models`, `pathway-enrichment-analysis`, `sc-rnaseq`
- Clinical: `cohort-builder`, `phi-deidentifier`, `rwe-cohortstudy`, `semantic-builder`
- Others: `accelerators`, `presentation-builder`, `scientific-figures`, `skill-eval`

**Catalog and site**

- README and landing-page tables generated from each skill’s `category` and `summary` (`docs/hooks/skill_catalog.py`)
- GitHub Pages landing page plus MkDocs Material guide under `/guide/` (one page per skill)
- Categories: Bioinformatics, Clinical, Others
- Dark/light theme (persists in `localStorage`; follows the OS until the visitor chooses)

**Authoring and CI**

- Pipeline and guide templates; `AGENTS.md` authoring rules
- `sync_skills_git2unity.py` to register skills on Unity Gateway
- `skill-eval` paired with/without-skill benchmarking (MLflow); BiomniBench-DA harness
- PR checks: skill quality, per-skill tests, catalog sync, docs `--strict` build, gitleaks

### Changed

Names that existed before this tag, now canonical in 1.0:

- `oss-models` → `open-weight-models`
- `payer-provider-measure-catalog` → `semantic-builder`
- `Clinical RWE` and `Payer and provider` → one **Clinical** category

`sync_skills_git2unity.py` never deletes skills. If you synced before 1.0, drop the
old `oss-models` and `payer-provider-measure-catalog` skills from your Unity Catalog
schema by hand.

Other changes:

- `open-weight-models` eval: moved from `tests/` to the standard `eval/` layout — shared harness, per-family settings and run rounds under `eval/models/<family>/` (TEDDY: teddy-001, teddy-002), the Sep 24 – Oct 7, 2026 TEDDY runs kept as round folder `runs_20260924/` (the never-evaluated Sep–Oct Geneformer notebooks removed), and the hand-built reference notebooks in a shared `eval/ground_truth/`
- `open-weight-models` eval: round folders (exported notebooks, run records, per-run scores) are git-ignored (new `.gitignore` rule `skills/*/eval/models/*/runs_*/`); the repo keeps each round's notes (folded into `ROUNDS.md`) and one `scores.json` per model family in `eval/models/<family>/`, and the latest round's `eval/baseline_scores.json` and `eval/with_skill_scores.json`, as other skills do.
- `open-weight-models` eval: `eval/eval_report.md` is now the one short report for the skill: takeaways, a with / without comparison per model family, results by round (Sep–Oct 2026, round 1 and the latest round 2, all with corrected checks), where the skill helps by category, the problems the runs found in the skill and where they are fixed, verdict, and limitations with next steps; each round's detail is in `eval/models/teddy/ROUNDS.md`. TEDDY round 2 (a clean rerun of all four runs with the fixed skill) is added under `eval/models/teddy/runs_20261027/`. New `eval/CHECKS.md`, generated by `eval/list_checks.py`, lists every scored check by category with its severity and why it matters

### Fixed

- `open-weight-models`: custom PyFunc inference controls now go in the REST body `"params"` field; the SDK's `serving_endpoints.query(extra_params=...)` is silently ignored by these endpoints (measured on TEDDY 2026-10-27). TEDDY guidance also drops a hardcoded Genesis Workbench Vector Search endpoint, corrects the vocabulary size, records both declared licenses, and passes the now-required `name=` to `EndpointCoreConfigInput`. Validation now requires comparing the wrapper with the model's own upstream preprocessing and inference; TEDDY drops out-of-vocabulary genes and applies upstream normalisation as upstream does; the skill asks before deleting or overwriting an existing table, index, endpoint or model version; the `run_go` gate for costly steps is always saved off, and is switched on for a run only when the request asks to deploy (a request that also says "write the code" still counts as asking to deploy). "VS" is spelled out as "AI Search". See `skills/open-weight-models/CHANGELOG.md`.

### Notes

- Site publish is `mkdocs gh-deploy` to `gh-pages` (GitHub-hosted runners cannot deploy Pages on this org). PRs still run `mkdocs build --strict`.
- The landing-page catalog needs JavaScript.
- Compliance (HIPAA and similar) remains the user’s obligation; see the README disclaimer.
